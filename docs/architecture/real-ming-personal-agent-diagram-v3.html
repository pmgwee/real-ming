04 · Chosen memory architecture

Five different persistence responsibilities; no single universal brain.

“Memory” is split so current operational truth, immutable evidence, derived knowledge, runtime convenience and work state cannot silently overwrite one another.

1 · Sources of Record

Current provider and domain records. Real-Ming may read or write only under adapter capability and policy.

2 · Provenance + Evidence

Candidate Envelopes, source hashes, immutable audit and canonical Agent Brain Project Evidence.

3 · Persistent Compiled Knowledge

Encrypted, cited, versioned Markdown in Trust-Domain roots; rebuildable from evidence.

4 · Hot Runtime Memory

Small, write-gated Hermes preferences, routing facts and vault pointers only.

5 · Operational State

Work Items, Approvals, schedules, worker leases, Outcome Reports and audit state.

↓ two governed evidence inputs feed one policy-controlled compiler

05 · Final memory migration pipeline

Capture → validate → compile → publish → project; never dump and never silently promote.

A daily note is an operational record. Only reviewed, source-backed conclusions may become durable Compiled Knowledge or approved Hot Runtime Memory.

Capture

Provider event, export, file, cited evidence or approved research output.

Envelope

Source ID · hash · captured/as-of · domain · sensitivity · roles · retention.

Validate

Reject secrets, verify authority and freshness, detect duplicates and conflicts.

Compile

Extract claims, reconcile, cite sources, categorize, create Wikilinks and articles.

Lint

Check citations, contradictions, staleness, islands, missing metadata and policy.

Publish

Atomic versioned generation; update index.md; append log.md; preserve predecessor.

Project

Projection Broker / Evidence Broker releases minimum context for role, task and purpose.

Use + file

Hermes answers or works; useful output re-enters as a candidate, never direct truth.
