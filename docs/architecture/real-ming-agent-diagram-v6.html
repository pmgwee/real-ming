For conversational intent, Hermes decides what is needed. Native slash commands may be handled directly by the gateway without an LLM. The steps below are a reading aid, not a mandatory custom state machine.

Accept + route

02Hermes

Understand

Answer, clarify, research or do substantial work. Pick a role playbook only when useful.

Act + iterate

Call native tools, skills, plugins or MCP. Read results, plan, code, test and choose the next action.

Coordinate a record

Only if called: link a task, fetch reconciled context, record an outcome or validate a managed action.

Digest + verify

Continue the native loop. Check actual outputs and tests; metadata alone is not proof of completed work.

06Hermes gateway

Render + deliver

Return Hermes’s formatted response and supported progress/media through the native Telegram adapter.

Simple question: 01 → 02 → 06. No artificial task, role ceremony, mandatory JSON or companion call.
Substantial job: the native tool loop repeats as needed; 04 is an optional tool interaction, not permission for every thinking step.

Extend the harness without claiming invisible guarantees

Integration contract

Native hooks provide useful seams, but their exact behavior matters. Existing consequential-action restrictions are not removed by moving Telegram to Hermes; they need tested enforcement at the actual execution boundary.

Use supported extension points

Native tool calls and plugin/MCP tools perform actions. Context hooks can add relevant personalization. Tool/session/task events can feed a CEO view. Tool hooks can block or request approval on supported dispatch paths without a replacement agent loop.

Prove coverage and failure behavior

The pinned ingress hook can fail open; the pre-LLM hook injects context once per turn, not before every API call. Some event observers can drop events. One approved shell call may contain many effects. Test these boundaries; do not promise universal secret exclusion or a complete audit from hook names alone.

Release gateIf an existing restriction cannot be enforced on a native path, keep the affected capability uncredentialed or narrowly scoped and report the gap. Do not silently remove safety requirements—or disable unrelated native features to hide missing integration work.

Prove the experience before declaring the platform complete

CEO acceptance · implementation sequence

The first milestone is a real native Telegram vertical slice. Local controlled tests remain valuable, but they must not stand in for the installed harness, authorized integrations and Ming’s actual phone experience.

  1. Reconcile design and requirements. V6 is the new design target; update the specification, ADR, acceptance scenarios and new implementation work before another long build. Keep the historical 44-ticket graph as history, not proof of native readiness.
  2. Establish native Hermes parity. Verify the pinned gateway, allowlist, native commands, formatting, typing, selected progress mode, media and session behavior. Stage safely; one deliberate, reversible bot-owner cutover—not two pollers.
  3. Prove an actual coding outcome. Hermes reads a designated test repository, edits files, runs tests and reports real evidence. A task acknowledgment or denied tool proposal does not pass.
  4. Add Ming’s skills and providers. Configure role/context playbooks and authorized source tools. Test real permitted reads, provenance and freshness; separately approve external writes. Simple chat remains task-free.
  5. Add only the needed companion behavior. Map native task IDs to Master Tasks, validate existing status meanings, keep one writer/scheduler, and test backend failure, replay and exact-action approval paths.
  6. Inspect a real run in the private dashboard. Evaluate native views first. Add the Real-Ming CEO view for missing cross-app needs. Verify event gaps, failures and recovered state; show results and evidence, never hidden reasoning or secrets.
  7. Prove memory and recovery. Read/write a designated native Obsidian note and cited wiki entry, verify publication ownership and chosen device access. Back up and restore sessions, tasks and knowledge; verify laptop-off operation before final rollback-VM deallocation.

Product promise: “I use Hermes normally. Real-Ming makes it understand my world and keeps the important cross-app outcomes connected.” Do not remove existing stores or migrate live records simply because a native feature has a similar name.
