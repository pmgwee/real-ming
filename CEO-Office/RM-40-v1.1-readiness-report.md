## 3. What is **not** proven

This is the section that matters most, and none of it is a reason to stop — it
is the difference between "the system works" and "the system is running your
life".

1. **No live provider has been exercised in the default path.** Every adapter
   is proven against the contract harness, which is a controlled double. Real
   Telegram, Notion, Google, Canvas, Microsoft 365, DuitSini and Vercel calls
   sit behind an opt-in flag. The contract harness proves the *shape* of each
   interaction, not that your accounts behave that way today.
2. **No LLM has been called.** There is no model credential in this system, so
   nothing has exercised a real completion. Model routing is proven as policy —
   cheapest adequate model, high-sensitivity work confined to local, refusal
   when local cannot do the job — not as traffic.
3. **The dashboard has not been opened by you.** It is proven in a real browser
   against controlled state, and it is served from the Azure control plane, not
   from a public domain.
4. **The 30-day backup rule is enforced by the backup adapter, not by the
   control plane**, which cannot see inside the backup store. The control plane
   purges what the adapter reports and records evidence only when the adapter
   proves the deletion — it cannot independently confirm nothing lingers.
5. **The append-only database triggers are unproven.** Six `RAISE(ABORT)`
   triggers guard the retention tables. Exercising them needs direct database
   access, which neither approved test seam provides, so they are correct by
   inspection only.
6. **`ceo-confirmed` career claims are unverified.** A claim labelled "CEO
   confirmed" is accepted at face value; there is no Approval record behind the
   label.

## 4. Rollback and recovery readiness

| Property | State |
| --- | --- |
| Restart safety | Proven. The vault's append-only purge log is reconciled on every sweep, so a committed deletion is not left without central evidence if the process dies between the two writes. Verified by reopening a second control plane on the same state. |
| Idempotency | Proven. Repeated retention sweeps, repeated job runs and replayed commands produce one record, not two. |
| Deployment rollback | Proven. Promotion is bound to an exact candidate version; the predecessor stays readable. |
| Financial history | Proven. Snapshots supersede rather than overwrite; the predecessor workbook survives byte-for-byte. |
| **Off-host backup** | **Not in place.** Local backup meets every acceptance criterion, but losing the Azure VM loses the operations state. This is the single largest recovery gap. |
